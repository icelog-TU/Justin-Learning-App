# 古文破譯家 App 實作契約

## 何時讀取

只在下列任務讀本檔：

- 把已核准教材轉成正式 App；
- 修改古文共用資料模型、互動狀態、獎勵、進度或完成流程；
- 對正式 App 做完整內容與互動驗收。

純教材撰寫、選題或一兩題文案審稿不讀本檔。

## 實作輸入

開始前必須具備：

- `GUWEN-PROJECT-STATUS.md` 指定的唯一 active 主檔；
- 清楚的核准範圍；
- 現行 App 原始碼、型別、路由、進度、獎勵、語音與測試；
- repository 指示與固定分支最新版。

缺少 active 路徑或核准邊界時停止，不得從 skill 範例、archive、聊天附件或另一份同篇教材猜測。

## 權威與內容邊界

依序採用：

1. 使用者目前任務的明確指示；
2. active 主檔中的已核准內容；
3. 現行程式碼與型別；
4. 本契約與 App skill；
5. 實作者的改善建議。

不可自行改動：

- 古文全文、字詞、語序與版本；
- 真實古文線索；
- 作者、篇名、出處、是否節錄等事實；
- 已核准現代文案、選項順序、正解、回饋、提示與證據邊界；
- 核准的題目順序、解鎖關係與完成流程。

可以提出改善建議，但必須列出位置、目前版、建議版、理由、教學影響與實作影響，取得明確核准後才採用。未核准時實作既有基準，不得自行停工或改寫。

## 顯示權限

| 類別 | 孩子端 |
|---|---|
| 原文、任務、線索、問題、選項、回饋、提示、詳解 | 依核准流程顯示 |
| 線索出處 | 卡片上顯示，不朗讀 |
| 成人編輯、來源查核、斷句討論、實作備註 | 禁止顯示與朗讀 |
| 最終白話驗證 | 完成全部必要步驟後才顯示 |

預載資料、折疊區、ARIA、CSS class、測試 id 或 DOM 順序都不得提前洩漏答案或最終白話。

## 資料與狀態

- 使用穩定且唯一的 lesson／step／closing id。
- 以 `prerequisiteIds` 表達解鎖，不以陣列索引保存進度。
- 保留來源、線索、局部白話、未知邊界、鑰匙與成人資料的分離。
- 既有 schema 不足時做最小可重用擴充，不刪教材內容來遷就 schema。
- 新欄位必須兼容舊 localStorage／Firestore；需要重置舊題進度時使用明確 content revision。

一般步驟至少具有：

```text
locked → available → attempted_wrong → solved
```

- `locked`：先備未完成，不能作答。
- `available`：按核准順序顯示引導、線索、問題與選項。
- `attempted_wrong`：保留選項，只顯示證據導向提示，不公布正解。
- `solved`：依下節的立即獎勵、核心解答、選擇性詳解順序呈現。

## 答對後的固定順序

1. 立即隱藏選項、記錄答對並發放一次金幣與星星；同時播放成功音效及獎勵動畫，保留選對後的立即回饋。
2. 獎勵效果結束後，以獨立「核心解答」區塊顯示完整的 `correctFeedback`，並自動播放。
3. 核心解答播放期間只提供暫停、繼續與重新播放；不提供正常跳過，且「查看詳解」與下一題保持鎖定。
4. 核心解答正常播放完成後，持續顯示核心卡、獎勵摘要與取得的鑰匙，並同時提供「點我看詳解」及下一題。
5. 「點我看詳解」才展開獨立詳解卡；不得自動強制展開或播放。
6. 詳解只顯示與播放 `explanation`，不得把 `correctFeedback` 的後續段落移入詳解，也不得重播核心解答。
7. 詳解是可選補充；閱讀或播放不得成為下一題條件。孩子按下一題時，立即取消詳解語音並換題。
8. 若瀏覽器不支援語音、語音沒有回報完成或播放失敗，核心文字仍保持顯示；依字數經過合理閱讀時間後才顯示「我已讀完核心解答」備援。孩子明確按下後才能解鎖詳解與下一題。

所有延遲計時器在離頁、換題、reset 或 unmount 時清除。獎勵只由答對事件以 step id 防重發放；語音 `onend` 與閱讀 fallback 只能解鎖後續操作，不得發獎。

既有教材若仍以 `correctFeedback` 的空行分段保存舊式詳解，視為待遷移資料。不得直接刪除相容讀取而造成內容遺失；必須先取得教材修改範圍的核准，把核心之外的段落移入主檔 `## 詳解`／App `explanation`，逐題驗證後才能移除相容邏輯。所有新題與本次實際修改的題目直接遵守新欄位邊界。

## 題型與收尾

- `evidence`：兩條比較線索。
- `reconstruction`：有選項、正解與答錯狀態的鑰匙組合。
- `reveal`：教材明確不設選擇題的單純組合 checkpoint。
- `local_inference`／`story_reasoning`：依本篇上下文推論，不虛構跨篇線索。
- `sequenceOrderingClosing`：有正確順序的拖放排序。
- `causalChainClosing`：有選項與正解的因果推理；答案後才顯示因果鏈。
- `evidenceMultiSelectClosing`：嚴格比對每個勾選狀態。

依實際互動判斷型別，不以章節名稱猜測。Closing 是獨立 optional 欄位，不能為模仿前篇而強迫每篇全部使用。

所有有正解的 closing 也遵守相同的「立即獎勵 → 完整核心解答 → 才能繼續」門檻；不得因 closing 使用不同畫面，就在核心播放完成前顯示或啟用繼續、下一關或白話卷軸按鈕。

成人預覽與孩子端的題型結構以 `src/components/guwen/GuwenQuestionBlocks.tsx` 為單一實作來源。線索卡、作答前鑰匙、一般選項、排序卡、多選、因果鏈、核心解答與詳解不得在兩個 page 各寫一份。兩端只保留必要差異：成人預覽從 active MD 解析並模擬作答狀態，不寫入進度或獎勵；孩子端使用正式資料並執行真實作答、解鎖、獎勵與持久化。新增或修改題型時，必須先擴充共用元件與解析／資料映射，再同時驗證兩端。

全文白話驗證的 prerequisites 必須包含所有必要 step 與存在的 closing。完成流程、徽章與慶祝順序沿用 shared component；只有教材明確核准特殊流程時才新增可重用設定。

## 獎勵與進度

- 使用 `src/lib/rewards.ts` 與既有 mutation 路徑。
- 重玩倍率在一次 run 開始時固定；不能因完成時 `timesCompleted` 更新而反應式跳到下一級。
- 顯示的題目總數必須包含 closing。
- 快速連點或非同步回呼不得重複發獎。
- 離開再回來要恢復正確 step／closing／complete 狀態；全部已解但未寫入完成狀態時要有明確修復策略。

## 排版與發音

教材 MD 先在 `/#/guwen-draft-preview` 審排版與實際播放，正式 App 實作後再複核。

- 預覽與正式 App 共用 `speak()`／`speakSequence()`／`ttsSafe()`。
- 所有長段播放提供暫停、重新開始與停止；切換畫面取消上一段及未觸發的延遲播放。
- 出處、詳解中的成人資料與只顯示欄位不朗讀。
- 不做獨立多音字掃描、catalog、實聽台、中央回傳或兩階段結案。
- 舊 audit 狀態不阻擋核准、實作、commit、push 或部署。
- 實際念錯時只改語音輸入，保留畫面古文，並驗證相鄰用法不受誤傷。

## 驗收

至少檢查：

### 資料

- id 唯一、prerequisite 存在且無循環；
- 題序、選項順序、正解、線索與來源符合 active 主檔；
- 古文全文與真實線索逐字一致；
- 成人備註沒有進孩子資料；
- 未核准現代文案沒有進 App。

### 互動

- 鎖定、答錯、答對、重玩與恢復正確；
- 答對後立即發獎，獎勵結束才播放核心解答，核心完成前無法查看詳解或進下一題；
- 核心完成後可選擇詳解或下一題，語音失敗時只有延遲出現的閱讀確認可解鎖；
- 詳解播放不重播核心解答，按下一步可隨時跳過詳解；
- closing、白話卷軸、完成慶祝與徽章順序正確；
- 手機觸控、鍵盤與螢幕閱讀器不洩題。

### 工程

```bash
npx tsc -b
npm run build
```

依變更另跑格式、preview parser、TTS 或瀏覽器測試。完成後回報修改檔、資料／狀態變動、測試、古文逐字一致性、核准過的文案變更及尚待確認事項。
