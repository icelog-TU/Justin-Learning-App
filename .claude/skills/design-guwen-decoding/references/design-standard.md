# 古文破譯題設計標準

## 1. 認知模型

每一道題都應形成以下證據鏈：

> 未知古文 → 已知古文線索 → 找共同特徵 → 選擇最佳假說 → 放回原文 → 更新故事畫面

選擇題只是提交推論的介面，不是學習活動本身。真正的學習活動是比較古文證據。

## 2. 教材編輯前置作業：斷句

斷句會改變字的角色與整句畫面，因此教材設計者必須在出題以前完成判斷。這是成人編輯工作，不是 App 中讓中低年級孩子作答的關卡。

遇到歧義時，製作下列表格：

| 候選斷句 | 必須成立的句法 | 要尋找的證據 |
|---|---|---|
| A／BC | A 能獨立擔任句法角色；BC 是可成立組合 | A 的同型句、BC 的古文用例 |
| AB／C | AB 是可成立組合；C 能接續或補足 | AB 的古文用例、C 的同型句 |

判斷優先順序：

1. 同篇上下文能否形成完整事件。
2. 同時代或相近語體是否有相同句型。
3. 動詞需要的主語、賓語或處所是否齊全。
4. 哪種切法需要較少省略或牽強補字。

若學界或版本本來就存在差異，呈現暫定結論，不要偽裝成唯一答案。

除非使用者明確要求高階斷句活動，否則：

- 不向孩子展示候選斷句；
- 不要求孩子判斷標點；
- 不把句界當成選擇題；
- 先由教材設計者決定目標單字或短語，再進入跨古文破譯。

## 3. 線索准入條件

每條古文線索必須：

- 真實可查；
- 與目標用法相同或高度相近；
- 即使加上已破解白話，仍保留可比較的目標字；
- 長度適合孩子在單一畫面閱讀；
- 兩條合起來能產生交集，而非各自指向不同義項。

優先選擇具體動作或可見畫面。若原句太長，只截取完整且不失真的短語，並標示出處。

## 4. 已破解白話的功能

白話只解鎖「線索句」，不解鎖「目標句」。保留目標字的未知位置，例如：

> 抱【甕】而出灌。  
> 已破解為：有人抱著「甕」走出來，用它澆水。

這段白話提供關係證據：可抱、可裝水、可用來澆；它不直接說「甕＝容器」。

## 5. 選項設計

好的選項是三個競爭模型：

- 正解能解釋全部線索。
- 干擾一受到某個表面詞吸引，但不能解釋另一條線索。
- 干擾二在方向、物件類別、句法角色或因果上錯誤。

避免：

- 一長兩短，讓答案由形式暴露；
- 一個合理、兩個荒謬；
- 直接複製已破解白話作為正解；
- 要求孩子靠現代常識猜，而不用比較古文；
- 每題正解固定在同一位置。

## 6. 詳解模板

按順序填寫：

1. **線索一畫面**：完成目標動作後，誰／什麼發生了什麼？
2. **線索二畫面**：第二句提供了哪一條獨立證據？
3. **交集**：兩句共同限制出什麼特徵？
4. **選擇**：哪個假說能同時解釋兩句？
5. **排除**：其他假說各自在哪條證據上失敗？
6. **暫定破解**：因此，目前可推得……
7. **保留未知**：僅憑這些線索還不知道……，要回原文繼續找。

使用「目前可推得」而非「這個字就是」，讓孩子保留可更新的理解模型。

## 7. 組合破譯

當目標句含兩個以上已破解部分時，先展示密碼鑰匙：

| 密碼 | 已取得的線索 |
|---|---|
| X | 暫定功能或意思 |
| Y | 暫定功能或意思 |

再依原文順序組合。選項可借用舊線索的事件作干擾，但詳解必須說明：舊事件是證據來源，不是本篇情節。

## 8. 難度與耐心

高強度推理不等於高閱讀負荷。

- 每畫面只做一個判斷。
- 引導語最多兩個短句。
- 一次顯示兩條線索即可。
- 答錯提示指出應重新比較的證據，不說答案。
- 詳解可完整，但先顯示一句短回饋，再讓孩子展開閱讀。

## 9. 選題判準

值得出題：

- 不理解便無法重建事件；
- 古今義不同；
- 代詞指涉或虛詞關係影響理解；
- 能透過其他古文找到清晰、可比較的證據；
- 能支援後續句子組合。

通常不值得單獨出題：

- 從字形或現代用法即可立即理解；
- 即使不知道也不影響故事；
- 找不到簡短而同義的古文線索；
- 只是為了讓每個字都有一題。

## 10. 品質檢查

交稿前逐項確認：

- 教材設計者是否已先處理斷句歧義，且沒有把這項負擔轉交給孩子？
- 是否真的使用其他古文，而非現代中文例句？
- 兩條線索是否指向同一用法？
- 孩子是否必須比較兩條證據？
- 正解是否只是暫定到證據所允許的範圍？
- 詳解是否先談畫面與證據，最後才命名意思？
- 是否把破解結果放回原文？
- 是否區分基本意思與本篇新增資訊？
- 是否維持短畫面、低閱讀負荷？

## 11. 全文核准定稿後的多音字實聽關卡

- 自第四篇起，逐題寫作時只標明「會播放／只顯示」，不逐題掃描、不維護候選表、不預加讀音提示；第一至第三篇既有表格保留作歷史紀錄，不回溯清理。
- 全篇核准定稿且沒有待審文字後，再獨立掃描任務開場、本篇原文、App 引導語、古文線索、破解白話、任務／題目、選項、答對回饋與答錯提示。詳解、成人／出處及純顯示文字排除。
- 抓出播放白名單中全部多音字，不得只選 agent 猜測容易念錯的字；合併完全相同句子後，按字形、指定讀音、讀音相關用法及相同 TTS／voice 條件分組。
- 每組只留一個代表 target，以最少完整代表句覆蓋所有群組並加入 `src/data/guwenPronunciationAudit.ts`。部署並開啟 `/#/tts-audit` 後才算正式建檔。
- 只有使用者能在孩子實際裝置逐句親耳判斷；句內每個目標分別按「念對／念錯」，全部選完才回傳，agent 與自動測試不得代填。
- 代表目標結果可套用到同一已核准讀音群組；念對群組不加註，念錯群組的每個白名單位置都就近加提示。不同讀音、用法或 TTS／voice 條件不得共用結果。
- 所有判定必須成功回傳中央資料庫並有回傳編號；實聽後由 agent 執行 `npm run tts:audit:pull` 讀回核對。
- 歷史統計不能跨越讀音群組；目前只在字形、讀音、用法及 TTS／voice 條件相符時沿用代表結果。
