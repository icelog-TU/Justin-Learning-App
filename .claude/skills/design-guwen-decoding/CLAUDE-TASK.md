# 古文破譯家 App｜Claude Code 交接任務

## 一、任務目標

請把本交接包中的《司馬光破甕救友》完整教材放進現有的「古文破譯家」App。

這不是一般的古文字義選擇題。核心學習方式是：

1. 孩子先看尚未破解的古文。
2. 遇到關鍵字詞時，讀取其他真實古文中的短線索。
3. 線索附有孩子已經知道的白話意思。
4. 孩子比較相同字詞在不同古文中的用法，提出有證據的推測。
5. 解開字詞後，再把意思放回原句，逐步重建事件。
6. 全篇破解完成後，才開放完整白話文，讓孩子驗證自己的理解。

App 中的 AI／引導角色是破譯助手，不是直接公布答案的老師；孩子是古文破譯家。

## 三、內容修改權限

### 3.1 不可自行改動

以下內容必須逐字保留，不可為了配合 UI、資料模型或個人偏好而改寫：

- 教材中的古文原文
- 跨文本古文線索的古文字句
- 古文線索的字序、用字與已確認的版本
- 已確認的作者、出處及版本資訊

若發現異文、疑似錯字、出處問題或史實問題：

1. 不要直接修正。
2. 列出目前版本、建議版本、依據與影響範圍。
3. 等使用者確認後再修改。

### 3.2 可以提出改善建議，但必須先討論

以下內容可以改善：

- 白話破解
- 題目敘述
- 選項與選項順序
- 答錯提示
- 詳解
- 最終白話文
- 畫面順序
- 互動方式
- 視覺呈現與兒童可讀性

但在正式採用前，請先以表格提出：

| 位置 | 目前版本 | 建議版本 | 修改理由 | 對學習的影響 | 對實作的影響 |
|---|---|---|---|---|---|

等待使用者核准後才套用。若使用者沒有核准新提案，請直接使用教材檔中的現行版本完成實作，不要停工，也不要自行改寫。

### 3.3 教材編輯註記

教材檔中供成人、教材設計者或工程師閱讀的說明，不得顯示在兒童學習畫面。請把「兒童可見內容」與「編輯／實作註記」分離。

## 四、實作要求

### 4.1 保留破譯歷程

每個破譯單元至少應支援下列狀態：

- `locked`：前置線索尚未完成
- `available`：可以開始作答
- `attempted_wrong`：已答錯，顯示提示但不公布答案
- `solved`：已破解，可查看完整詳解並前進

不要把所有題目一次展開，也不要在答錯後直接顯示正解。

### 4.2 題目呈現

每一道題應能呈現：

- 目前要破解的原句或詞語
- 簡短、真實且已確認的其他古文線索
- 每條線索的已破解白話
- 需要孩子比較後才能判斷的選項
- 答錯時的證據導向提示
- 答對後的推理詳解
- 解回原句的結果

題目不是字典義辨認，也不是用現代中文例句猜古字。核心互動必須讓孩子感覺自己在比對古文密碼。

### 4.3 全文與白話文

- 古文原文可以依學習進度逐步亮起或解鎖，但文字本身不可改動。
- 完整白話文必須在必要的破譯任務完成後才開放。
- 白話文的用途是驗證孩子先前建立的理解，不是預先洩漏答案。

### 4.4 資料模型

先盤點現有 schema，再以最小而清楚的方式擴充。資料模型至少要能區分：

- 古文原文
- 破譯單元
- 跨文本線索
- 線索白話
- 選項
- 正解
- 答錯提示
- 答對詳解
- 原句重建
- 解鎖條件
- 成人編輯註記

如果現有 schema 無法忠實承載教材，不要刪減或改寫教材來遷就 schema；請調整 schema，並說明資料遷移或相容性影響。

## 五、工作流程

1. 讀完本交接包的規範與教材。
2. 檢查 App 現有架構與可重用元件。
3. 建立教材內容到 App 資料結構的對照。
4. 若有現代文案或互動改善建議，先提交提案表；古文異動一律先停下確認。
5. 使用核准內容或現行基準內容實作。
6. 驗證每一步的解鎖、答錯、答對、詳解與最終白話開放流程。
7. 執行專案既有的格式化、型別檢查、測試與建置。

## 六、完成時的回報格式

請回報：

1. 已完成的功能與學習流程
2. 修改或新增的檔案
3. 資料模型／schema 的變動
4. 實際採用的教材版本
5. 是否有經使用者核准的現代文案或互動修改
6. 古文原文與古文線索是否逐字保留
7. 測試、型別檢查與建置結果
8. 尚未解決的問題或需要使用者決定的事項

不要只回報「已放進 App」。請讓使用者能確認教材內容、破譯邏輯和程式行為都已正確落地。
